# DX 5, part 0: git is no longer policed in supervised containers — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** In a `supervised` container, `container/pre-bash.sh` stops blocking git and `gh` commands, so an agent can refresh its branch with `git fetch origin` and `git rebase origin/main`; every other mode keeps every rule.

**Architecture:** One flag, set from the mode the hook already reads, gates the git and `gh` rules. The other rules (git hook hijacking, `rm -rf`, `sudo`, uploads, Docker) stay for every mode. The container instructions and the docs that describe the old rules follow.

**Tech Stack:** Bash (POSIX ERE through `grep -E`, BSD and GNU), the existing test script `tests/test-pre-bash.sh`.

**Spec:** `docs/superpowers/specs/2026-11-11-dx-5-herdr-core-design.md`, decision 9 (§3), §5.8 and §5.11 part 0.

## Global Constraints

- Branch `agent/dx5-hook-git`, from `origin/main`; one pull request, `Refs #92`. Title: `fix: le hook ne surveille plus git dans les containers supervisés (DX 5, partie 0)`.
- Modes: `supervised` changes; `autonomous` (the default when no marker exists), `contributor` and the maintainer's machine (no marker, so `autonomous`) keep every rule exactly as today.
- Rules that no longer apply in `supervised`: `git push` (all forms), every `gh` rule, `git checkout|switch main|master`, the `git merge` policy, `git rebase`.
- Rules that stay in every mode: `git config … core.hooksPath|fsmonitor|sshCommand`, `rm -rf`, `sudo`, curl/wget uploads, Docker `--privileged`, host namespaces, bind mounts outside `/workspace`. The audit log is written in every mode.
- Bash: `set -e` in scripts, quoted variables, a comment on each non-obvious block. POSIX ERE only.
- Lean tests: the hook is a security boundary for the other modes, so the test cases below are the ones that guard it; nothing tests documentation.
- Docs and plan in English, `CLAUDE.md` and `container/CLAUDE.md` in French. Commits: conventional prefix, French message.

## Review Focus

1. **A `contributor` or `autonomous` command slipping through.** The gate must test for `supervised` exactly, so a missing, empty or unknown marker keeps every rule (Task 1, `expect_block` cases with an unknown mode).
2. **Chained commands in `supervised`.** `git status && rm -rf /workspace` must still be blocked: lifting the git rules must not short-circuit the rules after them (Task 1).
3. **`core.hooksPath` in `supervised`.** It stays blocked: nothing has yet confirmed that no host process runs git inside an agent's repository (spec §5.8) (Task 1).
4. **The maintainer's machine.** This repository's `.claude/settings.json` runs the same hook with no marker file: it must keep blocking `git rebase` and non-`agent/*` pushes (existing default-mode cases stay green).
5. **Instructions that contradict the hook.** `container/CLAUDE.md` must not keep telling a supervised agent that rebase is forbidden and merge is the only way to refresh (Task 2).

### Task 1: Gate the git and `gh` rules on the mode

**Files:**
- Modify: `container/pre-bash.sh` (the mode is read at lines 39-53; the git push policy at 55-96; the `gh` rules at 98-130; `checkout main` at 132-135; the merge policy at 137-151; `rebase` at 153-157)

**Interfaces:**
- Produces: a shell variable `POLICE_GIT` (`1` or `0`) in `container/pre-bash.sh`, set right after `FORGE_MODE`. No other file reads it.

- [ ] **Step 1: Write the failing tests**

In `tests/test-pre-bash.sh`, replace the block "supervised mode: no credential exists, so every push and every gh subcommand is blocked" (lines 180-187) with cases that expect the new behaviour, and add the guards:

```bash
# --- supervised mode: no credential exists and origin is a read-only mirror,
# so git and gh are not policed (spec DX 5, decision 9); the rest still is ---
expect_allow_as supervised 'git push origin agent/test-project'
expect_allow_as supervised 'git push origin main'
expect_allow_as supervised 'git push origin --delete agent/x'
expect_allow_as supervised 'gh pr view 42'
expect_allow_as supervised 'git checkout main'
expect_allow_as supervised 'git merge agent/other'
expect_allow_as supervised 'git fetch origin && git rebase origin/main'
expect_block_as supervised 'git config core.hooksPath /tmp'
expect_block_as supervised 'git status && rm -rf /workspace'
expect_block_as supervised 'git rebase origin/main; sudo ls'

# --- any other marker keeps every git rule ---
expect_block_as contributor 'git rebase origin/main'
expect_block_as contributor 'git merge agent/other'
expect_block_as unknown-mode 'git rebase origin/main'
expect_block_as unknown-mode 'git push origin main'
expect_block_as '' 'git checkout main'
```

- [ ] **Step 2: Run the tests to verify they fail**

Run: `bash tests/test-pre-bash.sh`
Expected: FAIL lines for the new `expect_allow_as supervised` cases (the hook still blocks them); the other cases pass.

- [ ] **Step 3: Implement the gate in `container/pre-bash.sh`**

Right after `FORGE_MODE=…`, set `POLICE_GIT=1`, and `POLICE_GIT=0` only when `"$FORGE_MODE" = "supervised"`, with a comment that cites the reason: no credential in a supervised container, `origin` a read-only mirror, only `agent/*` branches leave by `forge fetch`, control at the exits (spec DX 5, decision 9). Wrap the git push policy, both `gh` blocks (the supervised and contributor `gh` refusals and the autonomous `gh` subcommand rules), the `checkout|switch main` rule, the merge policy and the `rebase` rule in `if [ "$POLICE_GIT" = 1 ]; then … fi`. Drop the now unreachable `supervised` branches inside them (the "Container supervisé" push refusal and the supervised `gh` refusal), and update the header comment of the push policy accordingly. Leave the `core.hooksPath` rule and everything after it outside the gate.

- [ ] **Step 4: Run the tests to verify they pass**

Run: `bash tests/test-pre-bash.sh` then `npm run test:bash`
Expected: `0` failures; every pre-existing default, autonomous and contributor case still passes.

# Dev VM (contributor model, part 1) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** From the Mac, `forge cloud create|start|stop|rebuild` drive a dedicated AWS VM with nested virtualization where an agent runs every agent-forge test on the host itself, without any GitHub credential on the VM.

**Architecture:** OpenTofu (`infra/aws/`) creates the network, the dev VM and its cost guards; a new Ansible playbook (`ansible/contributor.yml` = `site.yml` + role `forge_contributor`) turns the VM into a forge host with the agent's clone, toolchain, bot identity and `contributor` mode; the laptop CLI records the VM as a new host kind `cloud` and reuses `forge install`'s resumable step machine. The relay (bot credentials, publishing) is part 2, planned after this part's acceptance run (spec §8).

**Tech Stack:** TypeScript on Node 24 (`node --test`), Bash, Ansible (ansible-core ≥ 2.20), OpenTofu with the `hashicorp/aws` provider ≥ 6.34.0, AWS CLI v2.

**Spec:** `docs/superpowers/specs/2026-11-07-dev-vm-contributor-design.md` (§5.1–5.3, §5.5, §5.6 without the relay, §5.9 partly, §5.10). Read it before any task.

## Global Constraints

- No personal value anywhere in the repository (code, tests, docs, OpenTofu defaults): no AWS account ID, region default, address, login, email, bot name. They live in `<laptop state>/hosts/<name>/cloud.json` and the inventory (`CLAUDE.md`, "Sécurité").
- No GitHub credential and no SSH agent forwarding to the dev VM; no IAM instance profile; no AWS credential on any VM.
- Bash: `set -e`, every variable quoted, preconditions checked first (`CLAUDE.md`, "Scripts").
- `pre-bash.sh` regexes stay POSIX ERE (`grep -E`), portable between BSD and GNU grep.
- Boundaries: OpenTofu only creates cloud objects; Ansible configures the VM's system and never the inside of Incus; `forge` laptop commands drive OpenTofu and Ansible and never touch a host's OS directly.
- `aws` provider pinned `>= 6.34.0, < 7.0.0` (nested virtualization in place since 6.34.0).
- Nested virtualization: `cpu_options { nested_virtualization = "enabled" }`; instance type default `m7i.2xlarge`.
- Instances: IMDSv2 required (`http_tokens = "required"`), `http_put_response_hop_limit = 1`, no `iam_instance_profile`.
- Lean tests (maintainer's preference): tests guard security-critical or data-losing behaviour, never documentation content.
- Language: new laptop TypeScript and docs in English; `CLAUDE.md` and `pre-bash.sh` messages in French, like the rest of those files. Commits: conventional prefixes, French messages, ending with the session's attribution line.
- Signing: the maintainer chooses at execution time (YubiKey-signed, or unsigned and re-signed later); never push.

## Review Focus

1. **A start or stop that would destroy the instance.** After a `git pull`, `infra/aws/` may differ from what was applied; a silent apply could replace the VM and lose the agent's disk. `forge cloud start|stop` must refuse any plan that creates or deletes a resource (Task 4, `applyQuiet` tests).
2. **A security-group change that forces replacement.** Changing the SSH CIDR must be an in-place update, or every start hits refusal 1: the rule is an inline `ingress` block of `aws_security_group`, never a separate rule resource (Task 2, checked by the Task 9 start/stop run).
3. **A wrong public address.** `checkip` answering an HTML page (captive portal, proxy) must stop the start, never write a bad CIDR (Task 4).
4. **The Claude token leaking on the Mac.** It travels only on ssh's stdin: never in an argv, never in a printed line, never in a file on the Mac (Task 6).
5. **Losing the agent's work or the OpenTofu state.** A playbook re-run never resets the clone (`update: false`, Task 3, checked in Task 9); nothing removes a `cloud` host's directory, which holds the OpenTofu state (Task 6).
